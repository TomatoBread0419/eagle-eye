# 🏗️ 系统架构说明

## 架构总览

Eagle Eye 采用五层架构设计：输入层 → Agent 层 → Prompt 控制层 → 多模型协作层 → 输出层。每一层职责清晰，层间通过结构化 JSON 契约通信。

---

## 第1层：输入层 (Input Layer)

### 职责
为系统提供数据和触发信号。

### 组件

| 组件 | 类型 | 说明 |
|------|------|------|
| **Alpaca API** | 实时数据 | 美股行情、持仓信息、账户状态 |
| **市场事件监控** | 异步 | 多源新闻信号（WallStreetCN、Google News、搜狗微信） |
| **Cron 调度** | 定时 | Hermes Agent Cron，支持精确到分钟的任务触发 |
| **行情数据** | 实时 | qt.gtimg.cn（腾讯行情）、yfinance（Yahoo 备选） |

### 输入类型

- **定时任务**：每日 08:00 扫描、21:30 开盘检查、06:00 盘后扫描
- **数据轮询**：每 60 分钟执行市场事件扫描
- **异常信号**：AI 检测到的持仓异动、板块轮动信号

### 设计要点

- **多源交叉验证** — 行情数据至少使用 2 个独立源（腾讯 qt + Yahoo）
- **容错降级** — 主源不可用时自动切换到备选源
- **DNS 劫持防护** — 全局 socket 补丁检测 198.18.0.x 劫持，自动回退 Google DoH

## 第2层：Agent 层 (Hermes Agent)

### 职责
承载所有 AI 工作负载，负责任务编排和工具调度。

### 组件

```
┌─────────────────────────────────────────────┐
│            Hermes Agent 运行时               │
├─────────────────────────────────────────────┤
│  ┌─────────┐  ┌──────────┐  ┌───────────┐  │
│  │ 扫描器   │  │ 决策Agent│  │ 审计Agent │  │
│  │ Screener│  │ Trader   │  │ Auditor   │  │
│  ├─────────┤  ├──────────┤  ├───────────┤  │
│  │ 87只候选 │  │ 订单意图  │  │ 行为指纹   │  │
│  │ 池评分   │  │ 生成     │  │ 审计     │  │
│  └─────────┘  └──────────┘  └───────────┘  │
│  ┌─────────┐  ┌──────────┐  ┌───────────┐  │
│  │ 日报Agent│  │ 自校准   │  │ 风控Agent │  │
│  │ (报告)   │  │ (参数优化)│  │ (验证器)   │  │
│  └─────────┘  └──────────┘  └───────────┘  │
└─────────────────────────────────────────────┘
```

### 关键设计

**1. 工具即能力** — 每个 Agent 拥有的工具决定了它能做什么：
- `terminal` — 运行 Python 脚本、执行交易
- `read_file/write_file` — 读写状态文件、审计日志
- `cronjob` — 创建和管理定时任务
- `send_message` — 通过 WeChat 推送通知

**2. 任务隔离** — 每个 Agent 在独立的上下文中运行，不共享状态：
- 子 Agent 通过 `delegate_task` 异步执行子任务
- 结果通过 JSON 文件传递，非共享内存
- 崩溃不影响其他 Agent

**3. 状态持久化** — 所有运行状态存储在文件系统中：
- SQLite 数据库 — 审计日志、持仓历史
- JSON 状态文件 — 模式标记、自校准参数
- 日志文件 — 完整的行为记录

## 第3层：Prompt 控制层 (Prompt Control Layer)

### 职责
定义 AI Agent 的行为边界和输出格式。

### 三层 Prompt 体系

```
┌────────────────────────────────┐
│    1. System Prompt（全局）     │
│    定义角色 + 铁律 + 通用约束   │
│    "你是一个交易决策AI，永远... "│
├────────────────────────────────┤
│    2. Task Prompt（任务级）     │
│    定义当前具体任务 + 背景信息   │
│    "扫描87只候选池，选出top5..." │
├────────────────────────────────┤
│    3. Output Schema（输出级）   │
│    定义输出 JSON 结构和字段约束  │
│    { candidates: [{ticker,     │
│      score, rationale}] }      │
└────────────────────────────────┘
```

### 宪法规则 (Constitution Rules)

不可违反的铁律，写在 System Prompt 的最前面：

```
#1  AI不可删除系统生成的订单
#2  无止损单不建新仓
#3  永不执行未知来源的订单
#4  每笔交易必须记录审计日志
#5  AI必须独立判断用户意图，不盲目执行指令
...
```

### 设计原则

- **Constraints over Instructions** — 用约束框定行为边界，而非手把手教每一步
- **Self-Correction 优先** — prompt 中预留自检步骤，AI 先自我审查看是否遗漏
- **稳定性优先** — 输出 Schema 经过 5+ 轮迭代，确保在不同模型上产生一致格式

## 第4层：多模型协作层 (Multi-Model Collaboration)

### 职责
根据任务复杂度选择合适的 AI 模型。

### 模型策略

| 模型 | 使用场景 | 月用量 |
|------|----------|--------|
| **DeepSeek-v4-Flash** | 日常任务：新闻扫描、生成报告、执行交易 | 95% |
| **DeepSeek-v4-Pro** | 复杂分析：架构设计、代码审计、问题诊断 | 5% |

### 路由逻辑

```
接到任务
  ↓
评估复杂度
  ├─ 简单（扫描、报告、状态查询）→ Flash（低成本）
  ├─ 复杂（架构重构、根因分析）  → Pro（高质量）
```

### 成本优化

- 缓存命中率 88-97%，大幅降低 API 调用
- Flash 处理 95% 日常任务，Pro 仅用于高价值推理
- Token 用量监控，月度预算控制

---

## 第5层：输出层 (Output Layer)

### 职责
将 AI 决策转化为可执行的动作和可读的报告。

### 输出通道

```
┌─────────────────────────────────────────┐
│            输出层                         │
├─────────────┬──────────────┬────────────┤
│ WeChat Bot  │  Alpaca API  │  本地存储   │
│ (通知/报告)  │  (交易执行)   │  (审计日志) │
├─────────────┼──────────────┼────────────┤
│ • 早间速报   │ • 市价单     │ • SQLite   │
│ • 持仓卡片   │ • 限价单     │ • JSON状态 │
│ • 异动预警   │ • 止损单     │ • 日志文件  │
│ • 日报       │ • 止盈单     │ • 存档     │
└─────────────┴──────────────┴────────────┘
```

### 输出格式规范

- 结构化报告 → `market_events_latest.json`（按 JSON Schema 契约）
- 交易执行 → `OrderIntent` + 订单状态机
- 通知消息 → 模板化（ClawBot 模板 / 纯文本双模式）
- 审计日志 → 追加写入 SQLite + 日志文件

---

## 层间通信契约

所有层间通信使用 JSON Schema 定义的结构化数据：

```json
// 输入层 → Agent 层（任务指令）
{"type": "scan", "universe": 87, "sector_focus": "半导体"}

// Agent 层 → Prompt 控制层（系统 prompt + task prompt）
{"role": "system", "content": "你是一个交易系统AI..."}
{"role": "user", "content": "扫描候选池，返回 top 5"}

// Prompt 控制层 → 模型层（组装后的完整 prompt）
{"model": "deepseek-v4-flash", "messages": [...]}

// Agent 层 → 输出层（决策结果）
{"action": "buy", "ticker": "MRVL", "shares": 10, "rationale": "..."}
```

# Eagle Eye V7.1 LTS — Refactoring Plan

> **Core principle: Preserve trading know-how. Refactor infrastructure only. Do not reinvent the strategy.**

## Source
ChatGPT architectural review → Master Specification document (2026-06-18).

## Mandatory Problems To Solve
1. Remove all Termux hardcoded paths
2. Split giant files (us_trader.py 1674行, us_screener.py 859行)
3. Replace JSON persistence with SQLite
4. Centralize all configuration
5. Add watchdog, health checks, retry and deployment standards
6. Support multi-platform deployment (Termux/macOS/Windows/Ubuntu/VPS/NAS/Docker/Cloud)

## Target Architecture

## Implementation Phases

### Phase 1: Foundation (30%)
- Project skeleton + all __init__.py
- core/config.py (replace hardcoded paths, load .env)
- core/logger.py (replace print() with structured logging)
- core/http.py (unified HTTP client with retry/proxy)
- core/cache.py (SQLite cache with TTL)
- storage/db.py (SQLite connection, WAL mode)
- storage/models.py (all table definitions)
- storage/repositories.py (CRUD, replace json.load/dump)
- Data migration script (JSON → SQLite, with backup)

### Phase 2: Execution Layer (20%)
- broker/alpaca.py (extract API calls from us_trader/us_portfolio)
- execution/orders.py (place_stop_order, place_market_order, cancel_order)
- execution/positions.py (get_portfolio, get_holdings, update_trail_stops)
- execution/executor.py (execute_mode, report_mode, main)
- risk/engine.py (check_account_risk, check_position_utilization)
- risk/drawdown.py (>12% stop buy, >20% halve positions)

### Phase 3: Strategy Layer (20%)
- strategy/indicators.py (all calc_* functions from us_common)
- strategy/screener.py (scoring, kelly, event bias, earnings)
- strategy/market_env.py (merge market_env + breadth + macro)
- strategy/signal_decay.py
- strategy/news.py
- portfolio/manager.py
- portfolio/kelly.py

### Phase 4: AI Layer (15%)
- ai/decision.py (generate_report, run_portfolio_analysis)
- ai/audit.py (compliance_audit + contract_validator)

### Phase 5: Monitoring (10%)
- monitoring/watchdog.py (retry → recover → notify → continue)
- monitoring/health.py (DB, API, disk, memory checks)
- scheduler/scheduler.py (cron management, failure retry)

### Phase 6: Deployment (5%)
- install.sh, start.sh, stop.sh, status.sh
- Dockerfile + docker-compose.yml
- Documentation updates

## Risk Rules (unchanged)
- AI cannot directly trade: Hermes → Decision Engine → Risk Engine → Execution Engine → Broker
- Risk Engine always has veto authority
- Never hardcode secrets (.env + os.getenv)

## Phase Gate Criteria (each phase)
1. ✅ Feature functional
2. ✅ Paper trading normal
3. ✅ Rollback mechanism exists
4. ✅ Smoke test passes
5. ✅ Only then proceed to next phase

## Rollback Strategy
- Keep old scripts (don't delete)
- Keep JSON data files (don't delete)
- Keep SQLite backups
- Keep Git history
- Rollback command: `git revert HEAD`

## Key Constraints
- **Strategy unchanged**: 13-dimension scoring, Kelly formula, stop tiers, FOMC rules, sector leader avoidance — ALL preserved exactly
- **Parameters unchanged**: Only loading method changes (.env + SQLite), not values
- **Each phase independent**: Runnable, rollback-able, smoke-testable
- **Backward compatible**: Old scripts remain during Phase 1-3

## Platform Requirements
Android Termux, macOS, Windows, Ubuntu, Linux VPS, NAS, Docker, Cloud VM.
Unified startup: `python main.py`

## Database Tables
trade_history, positions, market_env, signal_decay, portfolio, compliance_logs, audit_logs, health_checks, scheduler_jobs

## Document Extraction Technique
.docx files can be read without python-docx: use zipfile to read word/document.xml, then regex to strip XML tags. Works on Termux with zero dependencies.

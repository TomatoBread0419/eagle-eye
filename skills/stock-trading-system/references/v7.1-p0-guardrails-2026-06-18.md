# V7.1 P0 Guardrails — 架构决策记录 (2026-06-18)

## 问题

LLM (deepseek-v4-flash) 是唯一决策者。脚本只做数据聚合，买卖决策 100% 发生在 LLM 推理中。策略存在于文档（auto_approval_policy.md），但代码层无拦截。

## 决策

新增三个硬守卫模块，将 LLM 从 Decision Maker 降为 Analyst。不改动任何交易逻辑（Kelly/Scoring/Threshold 零行变更）。

## 守卫模块

### 1. risk/policy_validator.py (~280行)
- `validate_order_intent(intent, portfolio_state)` → (PASS|REJECT, reason)
- 检查: Dashboard gate (§7), Active Sectors (§5), §6.1 Seed, Candidate confirmation (§6), Exposure (§5)
- 子函数: `check_dashboard_gate()`, `check_active_sectors()`, `check_exposure()`, `check_candidate_confirmation()`, `check_seed_eligibility()`
- `quick_portfolio_snapshot()` — 从 Alpaca API 构建验证用 portfolio_state

### 2. execution/candidate_tracker.py (~130行)
- `record_scan(symbols, details)` — 每次扫描后调用，记录候选出现
- `get_consecutive_count(symbol)` → int — 查询连续扫描次数
- `get_eligible_seeds()` → list — 获取今日 §6.1 合格种子候选
- 依赖: storage/models.py 新增 `candidate_history` 表

### 3. storage/models.py (+2表)
- `candidate_history`: symbol, scan_date, scan_count, last_seen, score, sector, kelly_pct, rsi, is_seed_eligible
- `policy_violations`: timestamp, symbol, check_name, result, reason, portfolio_snapshot

## 接入点: trade_executor.execute_mode()

```
OrderIntent 到达
  ↓
Gate 0: check_dashboard_gate() — 无 Dashboard → REJECT ALL
  ↓
Gate 1-3: validate_order_intent(intent, pf_snapshot)
  ├─ Active Sectors → §6.1 Seed check if <4
  ├─ Candidate confirmation → ≥2 scan cycles
  └─ Exposure → pos≤18% / sector≤30% / total≤90%
  ↓
PASS → Safety Check → OMS → Alpaca
REJECT → policy_violations log → skip
```

## 决策链对比

**之前:** cron → deepseek-v4-flash (Decision Maker) → 脑中判断 → us_trader.py → Alpaca

**之后:** cron → deepseek-v4-flash (Analyst) → OrderIntent → policy_validator (P0 gate) → Safety → OMS → Alpaca

## 测试结果

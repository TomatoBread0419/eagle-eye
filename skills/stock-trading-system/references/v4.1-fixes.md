# v4.1 代码修复记录 (2026-06-10)

## BUG #1 [严重] check_position_utilization() v4架构违反

**文件**: `us_trader.py` L476-510

**问题**: v4设计原则是"模式由AI判断，不是脚本自动检测"，但该函数仍读
`market_events_latest.json` 做关键词匹配（恐慌→防御，反弹→中性等），
覆盖AI传入的--mode参数。

**修复**: 
- 改为接受显式 `mode` 参数：`check_position_utilization(equity, cash, holdings, mode='normal')`
- 内部用 `MODE_MAP = {'aggressive': ('active', 0.55), 'normal': ('neutral', 0.50), ...}` 直接映射
- 删除所有关键词匹配代码
- 更新两处调用者：`main()` 传 `mode='cautious'`，`report_mode()` 传 `mode=mode`

## BUG #2 [严重] --stops stale highest 新仓位被立即清仓

**文件**: `us_trader.py` L125-145

**问题**: `us_risk_state.json` 中 `highest` 字段跨session残留。
同一symbol之前持仓过（更高价位→highest=$200），新买入（成本$150），
old_highest仍为$200→计算"从$200回撤到$150"→25%回撤→触发清仓。

**修复**:
- `set_highest(sym, price, state, cost=None)` 新增 `entry_cost` 跟踪
- 检测 `abs(price - stored_cost) / stored_cost > 0.30` → 自动重置 highest
- 四处调用者均更新传入 `cost=h['avg']`

## BUG #4 Alpaca API timeout 15s太紧

**文件**: `us_trader.py` L31, L142; `us_common.py` L17, L99

**问题**: DNS劫持环境即使有DoH修复也增加延迟，15s在网络抖动时不够。

**修复**:
- `us_trader.py`: `_url_get(timeout=30)`, `api_get(timeout=30)`
- `us_common.py`: `url_get(timeout=30)`, `get_daily_bars` 内部调用 `timeout=30`

## BUG #5 load_event_buy_signals() emoji匹配脆弱

**文件**: `us_trader.py` L543-550

**问题**: 优先级检测仅支持emoji（🔥🔥🔥→critical），
如果JSON里写 `"priority": "critical"` 会被默认降级为 "watch"。

**修复**: 支持文本+emoji双模式：
- `'critical'/'highest'` 或 `'🔥🔥🔥'` → critical
- `'high'` 或 `'🔥🔥'` → high  
- `'medium'/'watch'/'normal'` 或 `'🔥'` → watch

## 性能优化：扫描器并行化

**文件**: `us_screener.py`

**问题**: 78只股票串行扫描，DNS劫持下每只~40秒，总计~52分钟。

**修复**: `ThreadPoolExecutor(max_workers=10)` 并行请求，143秒完成（22x加速）。
新增 `_scan_one()` 工作函数，主循环改为 `as_completed()` 收集结果。

# 开盘挂单审核案例（2026-06-10）

## 场景

2026-06-10 21:04 BJT，US 市场即将开盘。用户说"美股开盘了"。

检查 cron 列表时发现「美股AI决策」cron（每小时运行）上次成功执行是 6/9 22:28。凌晨时段的几轮 cron 虽然脚本跑了但微信推送失败（断连），留下了一些历史挂单。

其中 **7笔市价卖单** 是之前 cron run 在 BJT 10:00-11:36 下的（US 前晚市场已关），状态全部 "new"。

## 结果

- 仓位从 53.6%（当前）→ ~50%（成交后），现金约 $50k
- 卖出：SNOW, IBM, UPS（3笔弱股）
- 买入：ARM, MU, PANW, NET, CSCO（5笔填补缺口）
- 科技：2.3% → ~3.5%（仍需大量补充）
- AI/云：6.9% → ~5.5%（SNOW换ARM+NET+PANW，质量提升）

## 教训

1. **不要信任跨 session 的挂单** — 每次开盘检查审计所有 pending orders
2. **板块感知是最高优先级** — 在缺配板块卖唯一持仓=自毁仓位
3. **保留龙头、替换弱者** — LMT(XOM/WMT 保留，SNOW/IBM/UPS 替换
4. **用户说"开盘了" = 跑完整开盘检查流程** — 不是只跑脚本

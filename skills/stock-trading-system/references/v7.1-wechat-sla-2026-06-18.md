# V7.1 WeChat Delivery SLA (2026-06-18)

## 目标

用户不需要打开 Pad 也能知道系统状态。

## 6条投递通道

| # | 通道 | 触发 | 频率 | 方式 |
|---|------|------|------|------|
| 1 | Heartbeat | system=ONLINE 确认 | 每小时 | no_agent cron → 微信 |
| 2 | Dashboard | AI决策完成 | 每轮交易 | AI cron → 微信 |
| 3 | Error Alert | emergency_stop触发 | 实时 | trade_executor → audit_log → 下个心跳 |
| 4 | Emergency Stop | 回撤>20% | 实时 | trade_executor → audit_log + 微信(cron输出) |
| 5 | Degraded Mode | API连续4次失败 | 实时 | degraded_mode → audit_log → 心跳检测 |
| 6 | Cron Failure | 交付错误 | 5分钟内 | cron_watchdog (每5分钟) |

## Heartbeat

**脚本:** `~/.hermes/scripts/eagle_heartbeat.py` (294行)
**Cron:** `8bce957367ec` — 每小时整点, no_agent=true

**输出格式:**
```
🦅 Eagle Eye Heartbeat
2026-06-18 17:00
system=ONLINE
dashboard=OK
health=GREEN
orders=7
checks=DNS=OK | API=OK(CLOSED) | DB=OK
```

**异常时附加:**
```
🚨 SYSTEM_OFFLINE — 心跳中断超过2小时
⚠️ EMERGENCY_STOP | DEGRADED
```

## SLA 规则

- 心跳每小时一次 → 微信
- 上次心跳 > 2小时前？→ SYSTEM_OFFLINE → audit_log
- 心跳恢复 → SYSTEM_RESTORED → audit_log
- 连续2次未发送 = SYSTEM_OFFLINE
- 恢复时自动检测并记录

## 审计日志

所有关键事件写入 `audit_log` 表 (event_type):
- `heartbeat` — 每次心跳 (severity=GREEN/YELLOW/RED)
- `system_offline` — 心跳中断 > 2h (severity=CRITICAL)
- `system_restored` — 心跳恢复 (severity=INFO)
- `emergency_stop` — 回撤触发 (severity=CRITICAL)，来源: trade_executor._log_audit_event()
- `degraded_mode` — 降级进入/退出 (severity=WARNING/INFO)，来源: degraded_mode._enter_degraded()/_exit_recovering()
- `policy_violations` — P0 守卫拒绝 (severity=WARNING)，来源: policy_validator

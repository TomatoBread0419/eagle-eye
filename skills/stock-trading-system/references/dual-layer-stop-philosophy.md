# 双层止损机制：为什么硬止损永不动

## 架构

```
硬止损 (Alpaca stop order)        软止损 (us_trader.py 追踪止损)
─────────────────────────        ──────────────────────────
挂上去就不动                      每轮 cron 重算波动率
建仓时计算一次                    最高价回调动态跟踪
网关挂了也执行                    cron 死了就不更新
永远不 cancel（死锁风险）         正常情况永远先触发
闪崩保险绳                        日常保护机制
```

## 为什么硬止损不跟着波动率调整

**不是因为做不到——是因为不该做。**

1. **死锁风险**：Alpaca cancel stop order → pending_cancel → 死锁。规则是"永不 cancel stop order"。

2. **保险绳不该聪明**：硬止损的存在意义是"你喝醉了、生病了、不在电脑前时的底线"。调整它是信任自己永远在线——但你不是。

3. **代价极低**：正常情况软止损永远先触发。硬止损只在闪崩（5分钟暴跌10%，软止损来不及反应）或 cron 进程死亡时生效。

```
COHR @$385, 波动100% → 硬止损 $346 (永不动)
涨到 $420, 波动降到30% → 软止损 $386 (跟着调)

跌到 $386 → 软止损触发，卖了
硬止损在 $346 —— 永远不会碰到
```

## 理论上唯一的漏洞：低波建仓 → 高波飙升

```
建仓时波动20% → 硬止损7% ($92 vs $100成本)
后来波动飙到100% → 但硬止损还是7%
```

这种情况硬止损比应该的10%更紧——**反而更快触发。** 7% 的窄止损在 100% 波动率下几乎一定会被噪音打掉。

但这个漏洞**自修复**：硬止损触发之前，软止损早就检测到波动率飙升并告警了。用 7% 还是 10% 的区别只差 3%。

**代价 3%，换来的是永远不碰 Alpaca stop order。** 值。

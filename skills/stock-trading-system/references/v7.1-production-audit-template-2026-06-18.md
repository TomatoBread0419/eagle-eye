# V7.1 Production Audit Template

**Provenance**: Generated 2026-06-18 during Eagle Eye V7.1 LTS production audit.

## Purpose

Operator-mode evidence package for independent auditing of the trading system. NOT a project report, summary, or presentation. Every finding backed by source code analysis.

## Section Template

### 01 Project Tree
- `find eagle_eye -type f | sort > 01_project_tree/project_tree.txt`
- Also include directory structure

### 02 File Statistics
- `find eagle_eye -name "*.py" -exec wc -l {} \; | sort -rn`
- Generate `largest_files.txt` sorted by line count
- Total line count + file count

### 03 Dependency Graph
- Extract imports from all .py files: `re.findall(r'^(?:from|import)\s+(\S+)', content, re.MULTILINE)`
- Map to layers: core/storage/broker/execution/strategy/portfolio/risk/ai/monitoring/scheduler/ops
- Flag cross-layer dependencies
- Check for circular imports

### 04 Forbidden Scan
```bash
grep -Rn "sys.path" eagle_eye/
grep -Rn "urllib" eagle_eye/          # should use core/http.py
grep -Rn "submit_order" eagle_eye/    # bypassing Risk Engine?
grep -Rn "from us_common\|import us_common" eagle_eye/  # V6 legacy
grep -Rn "requests\.(get|post)" eagle_eye/  # should use core/http.py
grep -Rn "hardcoded\|HARDCODED" eagle_eye/
```
Every match must include: file, line number, context. Do NOT suppress findings.

### 05 Trading Logic Fingerprint
For each component (Kelly formula, position sizing, signal thresholds, market regime, risk parameters, scoring rules, order flow, execution rules), mark exactly: UNCHANGED or MODIFIED.
If MODIFIED: show original, new, and reason.
List source file + line number for each component.

### 06 Database Schema
- `.tables` + `.schema` from SQLite
- `database_table_inventory.md`: purpose, row_count, legacy_source, dependencies for each table
- Detect: duplicate tables, temporary tables, legacy JSON dependencies

### 07 Behavior Parity
- Use identical inputs (same date, same market data, same holdings)
- Run V6 and V7
- Compare: signals, buy list, sell list, Kelly outputs, exposure, order intents
- Target: 100% parity. Explain every mismatch.

### 08 30-Day Operations Plan
- Daily schedule: health checks, scheduler verify, broker connectivity, DB integrity, paper trading verify, audit log review
- Weekly: log rotation, SQLite backup, API latency review, risk metrics review
- Emergency stop checks + exposure review triggers
- Watchdog review checklist + owner review checklist

### 09 Technical Debt Register
For each item: ID (TECH-DEBT-XXX), Location, Description, Risk Level (LOW/MEDIUM/HIGH/CRITICAL), Mitigation, Accepted Debt? (YES/NO), Owner Approval Required? (YES/NO)

### 10 Rollback Plan
- Backup locations (JSON + SQLite)
- Step-by-step restore procedure
- Validation steps (smoke tests, health checks, V6 parity)
- Stop conditions (when NOT to rollback)
- Recovery checklist

### 11 Verification
- Import verification (all modules importable)
- Smoke test results (status + health commands)
- Schema verification (tables, row counts, integrity_check)
- File count, module count, total line count
- Forbidden scan results summary

## Output Format
- All evidence in plain text/markdown
- One archive: `eagle_eye_v7.1_lts_production_audit.zip`
- No narrative, no marketing language, evidence only

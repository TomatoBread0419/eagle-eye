## Motivation

Phase 3 (Execution layer) will split `us_trader.py` (1674 lines) into `broker/`, `execution/`, and `risk/`. Before that split happens, the infrastructure that those new modules depend on must exist:

- Broker adapter (so split execution modules don't call Alpaca directly)
- Degraded mode (so split execution modules check system health before acting)
- Trading lock (so split execution modules cannot bypass risk checks)
- OrderIntent (so decision → execution data flow is typed and validated)
- Order State Machine (so every order lifecycle is auditable)

## Design Principles

1. **No trading logic**: All 5 modules are pure infrastructure. No scoring, no Kelly, no signal generation, no market definitions.
2. **Singleton pattern**: `get_alpaca_client()`, `degraded_mode`, `trading_lock`, `get_order_state_machine()` — all singletons so state is shared.
3. **Constitution-aligned**: Each module implements a specific Constitution rule (see table in SKILL.md).
4. **Zero dependency on V6 scripts**: No imports from `~/.hermes/scripts/` — all imports are from `eagle_eye.core.*` or stdlib.

## API Failure Counting

`AlpacaClient` tracks failures internally. Each failed API call increments `_api_failure_count`. Each successful call resets it to 0.

```python
client = get_alpaca_client()
# After 4 consecutive failures:
degraded_mode.check_and_update(client.api_failure_count)  # → enters DEGRADED
```

The `check_and_update()` call pattern is:
- `degraded_mode.check_and_update(client.api_failure_count)` → returns True if state changed
- After recovery: 3 consecutive successes (api_failure_count==0 3x) → back to NORMAL

## Trading Lock Integration

The trading lock is independent from degraded mode but they interact:

```python
# Full check before any trade:
trading_lock.check(
    db_healthy=check_db(),
    api_healthy=client.is_healthy(),
    market_data_healthy=check_vix_spy(),
    market_open=client.is_market_open(),
    degraded_active=degraded_mode.is_degraded(),
)

if trading_lock.is_locked:
    # CANNOT trade — no bypass possible
    return
```

## Order Flow

```
Decision Layer (AI/cron)
  │
  ▼
OrderIntent(symbol, side, qty, type, ...)
  │
  ├── intent.validate()       — basic sanity check
  ├── intent.mark_validated()
  │
  ▼
Safety Check
  ├── trading_lock.is_locked?  → reject
  ├── degraded_mode.can_open?  → reject for buys
  ├── degraded_mode.can_add?   → reject for adds
  ├── degraded_mode.can_exit?  → always allow
  │
  ├── intent.mark_safety_checked()
  ├── intent.mark_ready()
  │
  ▼
OrderStateMachine
  ├── oms.create_order(intent)          → PENDING
  ├── oms.transition(id, VALIDATING)    — business rules
  ├── oms.transition(id, APPROVED)      — risk check passed
  ├── oms.transition(id, SUBMITTED)     — sent to Alpaca
  │
  ▼
Broker (alpaca_client)
  ├── client.place_order(intent.to_alpaca_payload())
  │
  ▼
  oms.transition(id, FILLED)            — order filled
  oms.transition(id, COMPLETED)         — settlement confirmed
```

## Known Limitations

1. `degraded_mode` is in-memory only — restart loses degraded state. Future: persist to SQLite.
2. `trading_lock` does not check market holidays (only weekday/weekend + Alpaca clock).
3. `OrderStateMachine` is in-memory — restart loses all order records. Future: persist to SQLite.
4. `AlpacaClient.get_bars()` uses IEX feed — may miss pre/post-market data.
5. Import path requires `~/` in `sys.path` — `main.py` should handle this.

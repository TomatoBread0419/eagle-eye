# V7.1 Phase 3-4 Execution & Strategy Extraction — Learnings

> 2026-06-18: Phases 3 and 4 completed in a single session.

## Phase 3: Execution Layer Extraction

### Subagent Trap
When using `delegate_task` to create modules that should import from peer modules being built simultaneously:
- The subagent may produce a **giant monolithic file** with all logic duplicated (1698 lines instead of the required 500)
- Instead of importing from `position_manager`, `order_manager`, `stop_loss_manager`, `take_profit_manager`, it inline-copied everything
- **Lesson**: After subagents complete, immediately verify the orchestrator file imports from peer modules, not duplicates them. Check `from eagle_eye.execution.position_manager import` vs `def analyze(...` somewhere in the file.

### Line-Count Enforcement
- `trade_executor.py` started at 1698 lines, had to compress to 499 via 3 rounds of trimming
- Techniques: combine multi-line dicts into single lines, merge import statements, remove blank lines, compress section headers from 3-line ASCII art to 1-line compact format
- The orchestrator's `main()` function is the biggest single chunk (~350 lines) — can't easily be split further without affecting readability

### Import Chain Debugging
- `position_manager.py` imported fine individually but failed when loaded via `from eagle_eye.execution.position_manager import analyze`
- Root cause: another module in the import chain (`stop_loss_manager`) had a stale `from us_common import get_volatility_stop_pct` with `sys.path.insert(0, '~/stock_trader')`
- Python's import cache can mask failures — after fixing, the import worked
- **Lesson**: When a module fails with "No module named 'us_common'", audit the ENTIRE eagle_eye/ tree with `grep -rn 'us_common\|sys.path'`, not just the failing module

### Post-Subagent Cleanup Checklist
After delegate_task creates multiple modules:
1. Verify orchestrator imports from peer modules (not copies logic)
2. Run `grep -rn 'sys.path.insert\|from us_common' ~/eagle_eye/`  
3. Test `from eagle_eye.execution.trade_executor import run_cli` end-to-end
4. Count lines: `wc -l ~/eagle_eye/execution/*.py` against 500-line limit
5. Verify thin entry: `wc -l ~/.hermes/scripts/us_trader.py` < 200

## Phase 4: Strategy Layer Extraction

### sys.path Dependency Audit
- After creating `strategy/indicator_engine.py`, multiple execution modules still had `sys.path.insert` + `from us_common` dependencies:
  - `position_manager.py` — fixed by subagent
  - `stop_loss_manager.py` — still had `sys.path.insert(0, STOCK_TRADER_DIR)` + `from us_common import get_volatility_stop_pct`
  - `trade_executor.py` — two inline `from us_common import calc_rsi` / `from us_common import get_volatility_stop_pct`
- **Lesson**: Creating a new import target isn't enough — must audit all consumers in the dependency tree

### __init__.py Function Name Mismatch
- Wrote `from eagle_eye.strategy.market_breadth import scan_breadth` but the actual function was `main()`
- Same for `signal_decay`: `scan_signal_decay` vs `main()`
- **Lesson**: Always verify function names by reading the module before writing __init__.py

### Indicator Engine Design
- `indicator_engine.py` is pure math — no HTTP, no API calls, no external deps except yfinance (optional, graceful degradation)
- Functions extracted from `us_common.py`: calc_rsi, calc_sma, calc_boll, calc_macd, calc_atr, calc_volume_metrics, calc_volatility, get_volatility_stop_pct, calc_correlation, get_yf_metrics
- HTTP functions (url_get, url_post, get_daily_bars, get_us_price) stay in `us_common.py` for backward compatibility
- `us_common.py` is now a legacy compatibility layer — not imported by any `eagle_eye/` module

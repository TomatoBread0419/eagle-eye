# V7.1 Phase 3 — Extraction Patterns and Lessons

> Date: 2026-06-18
> Context: Refactoring us_trader.py (1674 lines) into 5 single-responsibility modules

## Target Architecture

```
~/eagle_eye/execution/
├── trade_executor.py       (499 lines) Orchestrator: risk, events, buy logic, CLI
├── position_manager.py     (321 lines) State + data + analysis
├── order_manager.py        (236 lines) Order CRUD through AlpacaClient
├── stop_loss_manager.py    (353 lines) Dual-layer stop loss
├── take_profit_manager.py  (133 lines) Tiered take profit exits
```

## Hard Constraints

1. **No module exceeds 500 lines** — this was the hardest constraint. trade_executor.py went through 4 iterations (1698 → 1074 → 519 → 499). Required pushing event signals, replacement tracking, and tech_snapshot into position_manager and order_manager.
2. **No direct Alpaca API calls** — all through broker/alpaca_client.py. Sub-modules import from order_manager, which wraps AlpacaClient.
3. **No trading logic changes** — same thresholds, same calculations, same flow. Only reorganization.
4. **Thin orchestrator < 200 lines** — us_trader.py at 72 lines imports from 5 eagle_eye modules.
5. **No circular imports** — dependency graph is strictly layered:
   ```
   trade_executor → position_manager, order_manager, stop_loss_mgr, take_profit_mgr
   stop_loss_mgr → position_manager, order_manager
   take_profit_mgr → position_manager, order_manager
   position_manager → broker/alpaca_client
   order_manager → broker/alpaca_client
   ```

## Subagent Pitfalls

### Pitfall 1: Orchestrator subagent duplicates instead of imports
When using delegate_task for parallel refactoring, the orchestrator subagent may copy ALL logic into its file instead of importing from sibling modules. Result: 1698-line trade_executor.py instead of 499-line.

**Prevention:** Explicitly tell the orchestrator subagent to IMPORT from sibling modules, not duplicate. Also verify line counts after subagent completion — if a module is over the limit, the subagent failed.

### Pitfall 2: Missing re-exports in thin wrapper
The thin us_trader.py imported `api_get` and `report_buy_decision` from trade_executor, but those functions lived in order_manager (api_get) or were removed during compression (report_buy_decision).

**Prevention:** After writing the thin wrapper, verify all imports resolve by actually importing the module.

### Pitfall 3: Line compression can remove needed constants
`TP_DRAWDOWN_PCT` was removed during aggressive compression but was still referenced in `stops_mode()`. The false drawdown suppression check uses it.

**Prevention:** Search for all constant references before removing them.

## Backward Compatibility

The thin us_trader.py (72 lines) re-exports ALL functions that V6 code expects:
- From trade_executor: main, report_mode, execute_mode, stops_mode, run_cli, risk checks, event signals
- From position_manager: analyze, get_bars, load_state, save_state, get_highest, set_highest, get_trail_stop, get_sector, tech_snapshot, SECTOR_MAP
- From order_manager: get_portfolio, get_holdings, place_market_order, etc.
- From stop_loss_manager: update_trail_stops, update_stop_blacklist
- From take_profit_manager: execute_take_profit

Old scripts can still do `from us_trader import analyze, main` and everything works.

## Tests to Always Verify After Extraction

1. `import us_trader` — all re-exports resolve
2. `from eagle_eye.execution.trade_executor import run_cli` — orchestrator imports
3. No direct Alpaca API keys/URLs in sub-modules (grep for TRADE_URL, paper-api.alpaca.markets, APCA-API-KEY-ID)
4. All modules <= 500 lines; us_trader.py < 200 lines
5. Old scripts untouched (sha256 comparison)

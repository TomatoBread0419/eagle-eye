## Key Constraints Enforced

- **No direct Alpaca API calls** — all through broker/alpaca_client.py
- **No sys.path manipulation** — all imports via eagle_eye.* package
- **No us_common imports** — indicators extracted to strategy/indicator_engine
- **Kelly is a calculator only** — portfolio_manager decides, Kelly informs
- **Ops modules are observers** — read state, record events, never trade
- **Single responsibility** — each module ≤500 lines (trade_executor exactly 499)
- **Backward compatible** — us_trader.py is 72-line thin wrapper, V6 backup preserved

## Subagent Lessons (Phases 3–6A)

1. **Subagents duplicate logic when given too much context** — trade_executor came back at 1698 lines (had ALL logic copied). Fix: give explicit imports to use, not full source.
2. **Line count enforcement requires aggressive compression** — got trade_executor from 1698→1074→519→509→499 through iterative trimming.
3. **Import chain debugging** — us_common import errors came from stop_loss_manager (not the module being tested). Check ALL modules in chain, not just the target.
4. **Parallel subagents work for independent modules** — broker + risk in parallel, position_manager + order_manager + trade_executor in parallel. But trade_executor DEPENDS on the other four, so it must be built after.
5. **Callback injection for cross-module deps** — stop_loss_manager and take_profit_manager use set_replacement_logger() callback pattern to avoid circular imports with trade_executor.
